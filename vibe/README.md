# 赵云与阿斗（原生网页塔防 · 人机对战）

原生 **HTML + CSS + JavaScript + Canvas 2D** 实现的单机塔防小游戏。主界面为水墨风，玩法为 5×8 双半场、20 回合人机对战。
无任何第三方库、无 CDN、无网络图片、无在线字体：图标全部用 CSS 形状 / Unicode / 汉字绘制，水墨背景由 Canvas 生成。

> 最近一次迭代：**手机 / 触控适配**（见第十三节）；此前还完成了主界面左上角严格对齐、阿斗落在路径终点格 + 起点格传送门、武将「组合体」占两格并可拆字、备战席 = 离棋盘无限远的普通格子。

---

## 一、如何运行

**方式 1：直接双击（最简单）** —— 双击 `index.html`，浏览器用 `file://` 打开即可，功能完全正常。

**方式 2：本地静态服务器**

```bash
python -m http.server 8000
# 浏览器访问 http://127.0.0.1:8000/index.html
```

页面按竖屏手机比例设计（最大宽度 480px），Chrome / Edge / Firefox 桌面版与手机浏览器均可，**手机触控已完整适配**（见第十三节）。

### 3. 如何调整主界面数值

全部集中在 `game.js` 顶部的 **`UI_CFG`**：

```js
const UI_CFG = {
  gold: 461,                                            // 金币数
  stamina: { current: 25, max: 30, costPerGame: 1 },     // 体力：当前/上限/每局消耗
  rank: { index: 11, minor: 1, stars: 41 },              // 段位：大帝 ★x41
  player: { name: '无名小将', id: 10086, avatar: '赵' },  // 用户信息占位
  reward: { win: { gold: 20, star: 1 }, lose: { gold: 5, star: -1 } }, // 胜负奖励
  settings: { sfx: true, bgm: true, vibrate: true },     // 设置开关（占位）
  persist: false                                         // true = 存 localStorage
};
```

- **金币**：改 `UI_CFG.gold`（显示在左上角胶囊里）。
- **体力**：改 `UI_CFG.stamina.current / .max`；每局开始扣 `costPerGame` 点，体力不足会提示并弹出体力弹窗。想关掉体力限制把 `costPerGame` 设为 `0`。
- **段位名**：段位由 `UI_CFG.rank` 的 `index`（0=士兵，1=军士，2=校尉，3=少将，4=中将，5=上将，6=大将，7=元帅，8=诸侯，9=霸主，10=君主，11=大帝）与 `stars` 决定；段位表常量是 `RANK_NAMES`。
- **星星数量**：`UI_CFG.rank.stars`。大帝只显示 `★xN`；低段位显示 `★★★★☆` 这种 5 星制。
- **胜负加减星**：`UI_CFG.reward.win.star` / `lose.star`（默认 +1 / -1）。
- **持久化**：把 `persist` 改成 `true`，金币/体力/段位/设置会存进 `localStorage`（默认关闭，保证每次打开都显示配置里的初始值）。

### 4. 段位规则

- 段位从低到高：**士兵 → 军士 → 校尉 → 少将 → 中将 → 上将 → 大将 → 元帅 → 诸侯 → 霸主 → 君主 → 大帝**（12 级）。
- 前 11 个段位各有 **5 个小段位**（I~V），每个小段位 **5 颗星**：赢一局 +1 星，满 5 星进位到下一小段位，满 5 个小段位进位到下一段位；输一局 -1 星，会按同样规则掉星（最低停在 士兵 I）。
- **大帝** 是最终段位，只用星星累计：赢一局 `★x42`、`★x43`……（不会掉成负数）。
- 左侧栏 / 弹窗里的规则与百分比都在 `rankText()` / `starText()` / `rankProgressPct()` 里。

## 四、地图（云梦泽 · 5×8 矩阵定义）

### 1. 地图数据

地图只用一个 **5 行 × 8 列**的二维数组描述（`game.js` 顶部 `MAPS[0].matrix`）：

```
0 = 路径（怪物行走，不能放置）
1 = 空白格（开场的 6 个可放置格）
2 = 未开发格（需要铲子开垦成 1）
```

云梦泽当前矩阵（行 1 在上、行 5 在下，行 5 靠近我方底线）：

```js
matrix: [
  [2, 2, 2, 2, 0, 0, 0, 0],   // 行1
  [0, 0, 0, 0, 0, 2, 2, 0],   // 行2
  [0, 2, 1, 1, 1, 2, 2, 0],   // 行3
  [0, 2, 1, 1, 1, 2, 2, 0],   // 行4
  [0, 2, 2, 2, 2, 2, 2, 0]    // 行5：列0=敌方出生点，列7=我方「斗」
]
```

渲染成棋盘（我方半场）：

```
行1  锁 锁 锁 锁 路 路 路 路
行2  路 路 路 路 路 锁 锁 路
行3  路 锁 空 空 空 锁 锁 路
行4  路 锁 空 空 空 锁 锁 路
行5  路 锁 锁 锁 锁 锁 锁 路     ← 出生点 / 我方「斗」
```

- **路径连通性**：16 格路径首尾相连成一条通道（无分叉、无缺口），从 **左下角出生点(列0,行5)** 沿左列上行 → 行2 右行 → 行1 右行 → 右列下行 → **右下角(列7,行5) 的「斗」**。
- **敌方半场**自动生成为我方半场的 **180° 镜像**（敌方出生点在右上、敌方「斗」在左上），形成对角对战结构。
- **阿斗在路径最后一格内**：我方「斗」画在全局 (列7,行9) 的路径终点格正中，敌方「斗」画在 (列0,行0) 的终点格正中（`CFG.ADOU_OUT = 0` 表示不外移；改成 0.9 可放回棋盘外侧）。
- **传送门**：路径起点格上画一个旋转的蓝色漩涡传送门（底盘 + 三条旋转弧线 + 中心亮点 + 光晕，`G.time` 驱动动画）。我方在左下角 (列0,行9)、敌方在右上角 (列7,行0)。怪物 `dist = 0` 就是从传送门所在格出现，之后照常沿路径前进，**不影响任何路径逻辑**（`CFG.PATH_OUT = 0` 表示出生点就在起点格）。

### 2. 格子视觉（按截图风格）

| 类型 | 表现 |
| --- | --- |
| 路径（0） | **深红褐色方块 + 粗糙纹理**（每格固定随机画几道深浅短痕），连成一条清晰路线；敌方半场色调略深 |
| 空白格（1） | **实心奶白色方块 + 稍亮的边框**，无圆点/圆圈/虚线等装饰；选中待放置汉字时会加一圈琥珀色高亮 |
| 未开发格（2） | 与路径相近但**更灰、更暗的纯色方块**，无纹理（底部一条暗边表示未开发） |
| 分隔线 | 格子之间 1px 极细线；整张地图**外框加粗**（5px）做出边界感 |

### 3. 怎么测地图布局

1. 打开游戏进入对局，看路径是否连成一条从**左下**绕到**右下**的通道。
2. 浏览器控制台执行 **`ADOU.api.printMap()`**：会打印 5×8 矩阵、整张棋盘的字符图（路/空/锁）、以及双方出生点与阿斗坐标，例如：
   ```
   矩阵：
   [2, 2, 2, 2, 0, 0, 0, 0]
   ...
   棋盘：
   r0 路 锁 锁 锁 锁 锁 锁 路   ← 敌方半场
   ...
   统计：路径 32 格 / 空白 12 格 / 未开发 36 格
   ```
3. 也可以直接改一格的数字看效果：把某行的某个 `2` 改成 `1` → 该格立刻变成可放置的空白格。

### 4. 怎么调整路径与空白格

- **只改 `matrix` 里的数字**即可：`0` 路径、`1` 空白格、`2` 未开发格。
- 约束：`0` 的格子必须连成**一条**不自交的链，且只有两个端点（出生点与「斗」）；路径折点、出生方向、阿斗位置都由矩阵**自动推导**，不需要手写坐标。
- 端点判定：取「行号最大」的端点作为出生点（本例是左下角），另一个端点作为「斗」；两者会自动朝地图外侧延伸（左右优先）。
- 如果想让「斗」出现在左下角，把矩阵**左右翻转**即可（例如行 1 改成 `[0,0,0,0,2,2,2,2]`、行 5 改成 `[0,2,2,2,2,2,2,0]` 的镜像写法），出生点会自动落到右下角。
- 新增地图：往 `MAPS` 里再放一个 `{ name, bossNames, pal, matrix }` 即可（`pal` 是配色，可复制云梦泽那份改色）。

## 五、武将「组合体」与拆字（本次新增）

### 1. 规则

| 规则 | 说明 |
| --- | --- |
| **两个字各占一格** | 集齐某个武将名的两个字（如「赵」+「云」）后，它们**不会合并成一个格子**，而是各自占一格、组成一个「组合体」 |
| **相邻才能组合** | 地图上必须**相邻（上下左右）**；待放置区里则占两个槽位（手牌一行，视为相邻）。一个字在地图、一个字在手牌时，拖上去会自动把手牌那个放进**相邻空格**再组合；没有相邻空格则无法组合 |
| **整体攻击 / 升级** | 组合体按武将数值（伤害 / 攻速 / 范围 / 技能）作战，**只由武将名的第一个字代表出战**（「赵」打，「云」不打），击杀数与蓝条两个字共享，升级时两个字一起升（金将 5 级 / 紫将 3 级） |
| **主动拆开** | 把组合体中的**任意一个字拖到别的格子/槽位**即可拆开（拖到自己另一半上则保持组合）。拆开后两个字各自独立，**等级完全保留**（3 级赵云 → 赵 Lv.3 + 云 Lv.3） |
| **拆开后** | 单字**不攻击**（回到「素材」状态），可以：① 与另一个单字再次相邻组合成武将（等级取两者较高者）；② 与**相同单字**（同级）叠放升级，最高 5 级 |
| **位置合法性** | 拆开 / 组合都只发生在**合法空格**上（不会越界、不会与已有单位重叠）；每次操作后 `ADOU.api.validateState()` 都会校验组合体是否成对、等级是否一致、两个字是否在同一区域 |
| **回收 / 清空** | 把组合体中的一个字撤回待放置区、拖到「营」牌回收、或征兵清空待放置区，都会自动解除组合（不会留下悬空的半个组合体） |

### 2. 视觉与「整体」表现

- 组合体的两个格子用**金色（金将）/ 紫色（紫将）粗连线**连起来，两格正中间浮出**武将名牌**（如「赵云 Lv.2」），等级徽章只画在出战的那一个字上。
- **点哪一个字都是选中整个英雄**：两个格子一起被选中框圈住，攻击范围圆圈**以两个字的中点为圆心**（攻击、技能的原点也用同一个中点，所以显示的圆圈 = 实际打得到的范围）。点「赵」和点「云」看到的是完全相同的圆圈。
- 待放置区里的组合体槽位是**金色卡面 + 金色描边**（`.bench-slot.pair`），两个槽位都能拖、都能看范围。
- 从待放置区放置组合体时，**两个字会一起上阵**占相邻两格（手牌里点范围时，只预览「有相邻空格」的落点）；周围没有相邻空格时会提示并退化为拆开，绝不会留下「半个组合体」。

### 3. 怎么测拆字

1. **合成**：招募到「赵」和「云」两个单字（待放置区里会自动组合），把它们放到地图上相邻的两个空白格 → 出现金色连线与「赵云 Lv.1」名牌。
2. **拆开**：把「赵」拖到另一个空白格 → 连线消失，两个字各自独立；提示条与弹字都会说明「已拆开组合体（保留等级）」。
3. **等级保留**：先让组合体击杀几只怪升到 Lv.2/3（名牌上会显示），再拆开 → 两个字各自都是 Lv.3（选中时提示条会显示 `云 Lv.3（将领字）`）。
4. **再次合成**：把两个字拖回相邻位置（或把其中一个从待放置区放到另一个旁边）→ 自动重新组合，等级仍是拆开时的等级。
5. **相同单字升级**：拆开后把「赵 Lv.3」和另一个「赵 Lv.3」拖到一起 → 合成一个「赵 Lv.4」。
6. **控制台**：`ADOU.api.isPaired(单位)`、`ADOU.api.unlinkPair(单位)`、`ADOU.api.validateState()`（应返回 `[]`）。

## 六、待放置区（营旁边 5 格）机制

这 5 格相当于**放不上地图的格子**，用来暂存召唤出来的汉字。

| 行为 | 说明 |
| --- | --- |
| **内部合成** | 两个**相同**的汉字（同类型同等级的小兵 / 同名单字 / 同名武将）拖到一起即合成升级 |
| **内部交换** | 不能合成的两个汉字拖到一起 → **交换位置**（不是合成） |
| **不能攻击** | 待放置区里的汉字不会攻击、不积累蓝条（因为它离棋盘无限远），只有放到地图格子上才生效 |
| **点击看范围** | 单击某个汉字 → 它所有可放置的空位都会显示**攻击范围虚线圆圈**；**武将组合体点哪一个字都一样**（见第五节），圆圈以两个字的中点为圆心；再单击任意空白区域（路径 / 未开发格 / 地图边界）即关闭范围显示 |
| **拖拽放置** | 从待放置区拖到地图空白方块即上阵；拖动过程中落点格会显示绿框（无效红框），并预览范围；**拖到路径上不会弹任何提示，直接回到原位** |
| **拖回** | 地图上的单位可以拖回待放置区任意空格，恢复为可拖动状态 |
| **征地清空** | 待放置区满员（或已有兵）时直接点「征兵」：**先清空再生成新的 5 个**，不会叠加，因此**没有「遣散」按钮** |
| **回收** | 把地图上的单位拖到左下角「营」牌上可以回收（防止格子被彻底占死） |

> 状态管理：`benchAdd / benchRemove / clearHand / swapBench / swapBoardBench` 统一收口，保证「一个单位要么在棋盘格、要么在待放置区」；`ADOU.api.validateState()` 可随时自检（重复存在 / 坐标不一致 / 槽位索引错误 / 阵营错误 / 组合体是否成对）。

### 备战席 = 「离棋盘无限远的普通格子」

备战席的 5 个格子就是**普通格子**，只不过它们到棋盘的距离是 **`CFG.BENCH_FAR = Infinity`**：

- `ADOU.api.unitCenter(单位)` 对备战席里的单位返回 `(∞, ∞)` → 计算距离时永远是 `Infinity`，所以**它打不到怪、怪也打不到它**（第 2 条「不攻击」的规则就是这条距离规则的自然结果，不再需要特判）。
- 其余「格子内的逻辑」完全照常：**等级 / 合成升级 / 组合体 / 攻击范围显示**都和棋盘格一模一样。
- 因此备战席的 5 个格子**也会显示等级徽章**（右上角圆形数字，紫将紫色、金将/小兵褐色），规则与棋盘卡面完全一致（`showLevelBadge()`）：
  - 小兵 / 武将 / 组合体：一直显示等级；
  - 单字：`Lv.1` 不显示（避免嘈杂），`Lv.2` 起显示；
  - 组合体只在「出战的那个字」上显示；
  - 铲子不显示。
- 组合体的两个槽位会额外标出**武将名小标签**（如「马超」）并变成金/紫色卡面，一眼能看出哪两个格子是一对。
- 备战席里不会画棋盘特效（飘字、光环、攻击范围圈都画在棋盘坐标系里，无限远自然画不出来），棋盘上照常。

操作方式两种都支持：**拖拽**（按住拖到目标）或**点选 → 点目标格**（两步点击）；手势结束后的那次 `click` 会被自动屏蔽，不会和地图放置逻辑冲突。

## 八、怎么玩（战斗部分）

1. 点「开始游戏」→ 随机地图（云梦泽 / 长坂坡 / 赤壁）→ 进入 20 回合人机对战。
2. 棋盘上半场是**敌方（人机）**，下半场是**我方**，每方 5 行 × 8 列；怪兽从中间绿色分隔带出发走向各自的阿斗，双方阿斗各 3 点血。
3. 「征兵」消耗馒头随机获得 5 个汉字或铲子（第一次 10 个，之后每次 +5）；点「营」查看招募概率与武将对照表。
4. 拖动/点选待放置区里的汉字 → 放到棋盘上的**奶白虚线空白方块**；放错了可以拖回待放置区。
5. 两个相同小兵叠放可升级（最高 5 级）；凑齐武将名的两个黄字自动合成武将。
6. 选中「铲子」→ 拖/点到灰色未解锁格，可开垦成新的空白方块。
7. 武将攻击命中积累蓝条，蓝条满自动放技能；武将靠击杀升级（金将 5 级 / 紫将 3 级），等级显示在卡牌右上角数字。
8. 点错了想取消：单击路径 / 未开发格 / 地图空白处即可关闭攻击范围显示。Esc 也能取消选中。ADOU.api.printMap() 可打印地图矩阵。ADOU.api.validateState() 可做状态自检。ADOU.api.addStars(1) 可验证段位进位。\n9. 胜负：**人机阿斗先被打空 → 我方立刻获胜**；**守满 20 回合且我方存活 → 我方获胜**；**我方阿斗先被打空 → 失败**。

快捷键：`空格` 暂停/继续，`Esc` 取消选中。

## 十、假设与可调项

1. **「5×8 格子」的解读**：实现为每方 **5 行 × 8 列**，上下拼接成 10×8，敌方为我方的 180° 镜像。
2. **小兵攻击范围半径 = 刀 1.9 / 骑 2.9 / 枪 3.9 / 弓 4.9 格**：一律「差一点点到整数格」，所以**刚好打不到距离 2 / 3 / 4 / 5 格的敌人**，但圆圈看上去仍然是 2 / 3 / 4 / 5 格；范围**不随等级变化**，点击显示的范围和实际能打到的范围完全一致。想让某类兵能打到整格，把 `CFG.SOLDIER.刀.range` 改成整数即可（例如 `1.9 → 2`）。范围一律用**虚线圆圈**展示。
3. **铲子概率 11.2%**（小兵 65.3% + 武将 23.5% = 88.8% 的补足）。
4. **Boss 漏怪扣 2 血**；普通怪扣 1 血。
5. **经济**：每回合结束双方各得 `10 + 2×回合` 馒头。
6. **征兵清空**：`CFG.HAND_REROLL = true`。改成 `false` 会退回「必须有 5 个空位才能征兵」的老规则。
7. **武将技能中「和原版一致」的 5 位**（关羽 / 赵云 / 刘备 / 关平 / 关兴）按标准塔防实现一版，数值见 `SKILLS`。
8. **曹植按金将处理**。

## 十三、手机 / 触控适配

### 1. 触控交互

| 项目 | 做法 |
| --- | --- |
| **统一指针事件** | 拖拽全部走 Pointer Events（`pointerdown/move/up/cancel`），鼠标、手指、触控笔同一套代码 |
| **拖动阈值区分设备** | 鼠标 8px、**触屏 14px** 才算拖动（`CFG.TOUCH.DRAG_THRESHOLD*`）：手指按下时的轻微抖动不会被误判成拖拽，短按仍是「点击选中」 |
| **滚动/缩放不抢手势** | 棋盘、备战席、营地都是 `touch-action:none` —— 手指在棋子上滑动只用来拖棋子，页面不会滚动，也不会触发双指缩放 |
| **打断可恢复** | 手机来电、切后台、手势被系统抢走时会收到 `pointercancel`；`blur` / `visibilitychange` 也兜底取消拖动，棋子必回原位 |
| **震动反馈** | 落子/合成功一次短震、非法落点震一下（`navigator.vibrate`，不支持的设备自动忽略；鼠标操作不震动） |
| **系统菜单/缩放入侵** | 屏蔽 `contextmenu`（长按菜单）、`dblclick`（双击缩放）、`gesturestart`（iOS 双指缩放） |

### 2. 布局与显示

| 项目 | 做法 |
| --- | --- |
| **视口** | `viewport-fit=cover` + `maximum-scale=1, user-scalable=no`（配合 `touch-action:manipulation` 同时去掉 300ms 点击延迟） |
| **高度自适应** | `#app` 用 `100dvh`（带回退 `100vh`），手机地址栏收起/展开时不会出现半截空白或裁切 |
| **安全区** | `#app` 的 padding 用 `env(safe-area-inset-*)`，刘海屏与底部手势条不会压住 UI |
| **不整页滚动** | `html,body{overflow:hidden; overscroll-behavior:none}`：关掉下拉刷新与橡皮筋；只有**主界面在矮屏时**内部可滚动（`#menu{overflow-y:auto}`） |
| **触摸目标** | `@media (pointer:coarse)` 下把顶栏按钮、营牌放大到 44px，备战席格子放大到 56px |
| **窄屏（≤380px）** | 主界面字号/间距缩一档；底栏压缩营地与「征兵」按钮宽度，**优先保证 5 个备战席格子够大好点**（实测 320px 宽屏下每个格子 39px、360px 下 52px） |
| **矮屏（≤660px）** | 主界面最小高度降到 560px 并允许滚动，内容不会被裁掉 |
| **横屏提示** | 触屏设备横过来且高度很矮时弹出「请竖屏使用」提示层（点一下可忽略；桌面窄窗口不打扰） |
| **高清屏** | 棋盘画布用固定 800×998 逻辑分辨率再等比缩放（天然高清）；主界面水墨画布按 `devicePixelRatio`（上限 2）重绘 |

### 3. 怎么测

- **桌面**：直接开 DevTools 的手机模拟（iPhone / 安卓预设都可），开「触摸」模式，试：手指按住备战席的字往外拖 → 页面不滚动、格子上出现绿框；松手落子；短按只选中不拖动。
- **真机**：手机浏览器打开 `index.html`（或同一局域网静态服务器地址），确认：不出现下拉刷新、双击不缩放、长按不弹菜单、刘海/手势条不遮 UI、转横屏有提示。
- **已实测**：360×740、320×568、390×844（含 DPR2）四种视口下，棋盘完整可见（格子 39~60px）、备战席格子 39~52px、触摸拖放与范围预览均正常、无控制台错误。
